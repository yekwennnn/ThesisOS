# ThesisOS application API

`thesisos-api` starts the production-facing FastAPI application on
`127.0.0.1:8000`. The transport is deliberately thin: immutable snapshot
ingest, JSON Schema/domain admission, artifact storage, diff review, and thesis
version promotion remain owned by the existing ThesisOS core.

## Configuration

Configuration is environment-only. No credential values are accepted in HTTP
requests or written to model-run provenance.

- `THESISOS_WORKSPACE`: immutable workspace root.
- `THESISOS_MODEL_ADAPTER_ARGV`: JSON string array for the provider-neutral
  adapter executable; defaults to `[]` (not configured).
- `THESISOS_MODEL_IDENTIFIER`: non-secret model/version label.
- `THESISOS_MODEL_TIMEOUT_SECONDS`: positive adapter timeout.
- `THESISOS_MAX_UPLOAD_BYTES`: positive upload limit; defaults to 50 MiB.
- `THESISOS_MAX_SOURCE_CHARS`: positive extracted-text limit.
- `THESISOS_OBJECT_STORAGE_PROVIDER`: `local` in this distribution. Other
  implementations use the `ObjectStorageProvider` interface and dependency
  injection.
- `THESISOS_FINANCE_PROVIDER`: `disabled` or `wind-cli`. Selecting `wind-cli`
  constructs the built-in bounded Wind provider at application startup.
- `THESISOS_WIND_CLI_ARGV`: JSON string array containing only the executable
  prefix, for example
  `["node","/opt/wind-mcp-skill/scripts/cli.mjs"]`. ThesisOS appends the fixed
  `call stock_data get_stock_basicinfo` route and its JSON parameters. This is
  never treated as a shell command string.
- `THESISOS_WIND_TIMEOUT_SECONDS`: positive Wind subprocess timeout; defaults
  to 60 seconds.
- `THESISOS_WIND_MAX_STDOUT_BYTES`: positive maximum Wind stdout size;
  defaults to 2 MiB.

The Wind API key is not a ThesisOS setting. Configure it only through the Wind
CLI's supported server-side secret mechanism. Do not put a key in
`THESISOS_WIND_CLI_ARGV`, an HTTP request, or a checked-in configuration file.
The application never returns the CLI argv, process environment, stderr, or
raw Wind response.

`GET /health` reports only `configured` and `available` provider states. It
never returns adapter arguments, environment values, or credentials.

The instrument resolver accepts a bounded stock code, calls Wind
`stock_data.get_stock_basicinfo`, and returns only a compact normalized record:
`symbol`, `name`, optional `exchange`/`market`/`industry`/`status`, `provider`,
and the UTC `as_of` retrieval time. Non-zero exits, malformed or ambiguous
responses, timeouts, and oversized output fail closed. Provider stderr and
backend messages are deliberately not reflected to clients.

Example server configuration:

```console
export THESISOS_FINANCE_PROVIDER=wind-cli
export THESISOS_WIND_CLI_ARGV='["node","/opt/wind-mcp-skill/scripts/cli.mjs"]'
export THESISOS_WIND_TIMEOUT_SECONDS=60
export THESISOS_WIND_MAX_STDOUT_BYTES=2097152
```

## Routes

- `GET /health`
- `GET /v1/finance/instruments/resolve?symbol=...`
- `POST /v1/sources/ingest` (multipart `metadata` JSON and `source` file)
- `POST /v1/companies/{company_id}/evidence/extract`
- `POST /v1/companies/{company_id}/model-runs/{run_id}/evidence/{evidence_id}/review`
- `GET /v1/companies/{company_id}/evidence/{evidence_id}`
- `POST /v1/companies/{company_id}/diffs`
- `GET /v1/companies/{company_id}/diffs/{diff_id}`
- `POST /v1/companies/{company_id}/diffs/{diff_id}/reviews`
- `POST /v1/theses`
- `GET /v1/companies/{company_id}/theses/current`
- `GET /v1/companies/{company_id}/theses/versions/{version_id}`

Errors generated by the application layer use
`{"error":{"code":"...","message":"..."}}`. Provider unavailability is
`503`, missing immutable records are `404`, and application/schema admission
failures are `422`.

Evidence extraction is a draft boundary. `POST .../evidence/extract` persists
the unreviewed array only inside its immutable model-run record; it does not
create files under `evidence/`. Admit one draft with the model-run review route
using `confirm`, `reject`, or `correct_statement`. Correction accepts only a
replacement statement; IDs, citations, source bindings, and model provenance
remain unchanged. Managed citation text is verified again immediately before
the reviewed Evidence and its review record are published together.

## Initial thesis bootstrap

Model-assisted initial ThesisCard bootstrap remains a separate future protocol
task. The canonical model runtime currently has versioned prompt contracts only
for `evidence-extraction` and `thesis-diff`; neither contract admits an initial
ThesisCard. Adding an HTTP route before defining a bootstrap prompt contract,
output shape, provenance record, and admission tests would create a path around
the system's auditable model boundary. A user-confirmed initial ThesisCard can
still be admitted through `POST /v1/theses`.

## OpenAI Responses adapter

Configure the bundled provider-neutral executable with server-side environment
variables:

```text
THESISOS_MODEL_ADAPTER_ARGV=["thesisos-openai-adapter"]
THESISOS_MODEL_IDENTIFIER=<Responses API model ID>
OPENAI_API_KEY=<server-side secret>
```

Optional settings are `OPENAI_BASE_URL` (HTTPS only),
`THESISOS_OPENAI_TIMEOUT_SECONDS`, `THESISOS_OPENAI_MAX_RETRIES`,
`THESISOS_OPENAI_RETRY_BASE_SECONDS`, and
`THESISOS_OPENAI_MAX_OUTPUT_TOKENS`. The adapter supplies the canonical prompt
and fully bundled canonical JSON Schema through the Responses API
`text.format`, with `strict=true` and `store=false`. It retries only bounded
transient HTTP/network failures and fails closed on refusal, incomplete,
failed, cancelled, queued, or malformed output. `OPENAI_API_KEY` is read only
inside the adapter process and is never emitted to stdout, provenance, or error
messages.
